# family-archive-designer

가족 아카이브 프로젝트 전용 UI/UX 스킬. 이 프로젝트에 한정된 구체적 컨텍스트를 담고 있다(다른 프로젝트에는 재사용하지 않는다 — 새 프로젝트가 생기면 그 프로젝트 전용 스킬을 새로 만든다).

## 언제
- 트리거: "가족아카이브 화면 만들어줘", "가족아카이브 UI 작업해줘", "가족아카이브 디자인하자".

## 핵심 컨텍스트 (고정)
- **구현 저장소**: `<family-archive 저장소 로컬 경로>`
- **설계 원본**: `projects/concepts/프로젝트_가족아카이브.md` + `projects/concepts/decisions/결정_가족아카이브_*`
- **타겟 사용자**: 가족 8명. 관리자(이승현)만 업로드, 나머지는 열람만. **부모님 등 비개발자·스마트폰 위주 사용자**가 있다는 게 디자인에서 가장 중요한 제약 — 모바일 우선, 큰 터치 타겟, 단순한 내비게이션, 최소 인지 부담을 항상 우선한다.
- **화면 구성 (2026-08-01 앨범중심UX재설계 이후 현재 구조)**: 홈(앨범 목록, 액션 3개는 목록 아래에
  위치 — [[../../projects/concepts/decisions/결정_가족아카이브_홈화면단일경로_20260803]]) → 앨범
  상세(그리드 뷰 + 그 안에서 바로 업로드, 그리드 클릭 시 별도 상세페이지 없이 PhotoSwipe 갤러리로
  즉시 확대) → `/albums/unassigned`(미분류 사진을 위한 가상 앨범 페이지, 그리드와 동일 컴포넌트
  재사용). `/upload`·`/review`·사진별 상세페이지는 전부 제거됨. 태그/인물 검색 없음. 비공개 링크
  접근 시 비밀번호 입력 화면 하나.
- **프레임워크**: Next.js(React) + Tailwind v4(CSS `@theme` 토큰, 별도 컴포넌트 라이브러리 없음).
- **⚠️ 사용자 생성 텍스트(앨범 제목 등)에 `truncate`(`white-space: nowrap`) 쓰지 말 것** — 긴
  한글 텍스트에 `truncate`를 걸면 모바일 브라우저가 그 nowrap 텍스트의 원래(안 잘린) 폭을
  기준으로 뷰포트 폭 자체를 잘못 계산해, 페이지가 확대되거나(그 결과를 `overflow-x:hidden`으로
  막으면) 화면 오른쪽이 통째로 잘려 보이는 실기기 전용 버그가 생긴다. 이미 두 차례 실제로 겪은
  버그([[../../projects/concepts/decisions/결정_가족아카이브_홈화면단일경로_20260803]] 이후
  기록, 앨범 목록 리스트 디자인 개선 때 `truncate`를 다시 넣었다가 재발) — 대신 자연스럽게
  줄바꿈되는 `line-clamp-N`(예: `line-clamp-2`)을 쓴다. `line-clamp`은 `white-space:nowrap`을
  설정하지 않아 이 문제를 원천적으로 피한다. 코드베이스에 `truncate` 사용처가 남아있으면
  안 되니(`grep -r truncate app/ components/`) 새로 추가하기 전에 먼저 이 규칙을 떠올릴 것.
- **디자인 톤: 파스텔, 4가지 색상 테마 선택형** — 2026-07-29 확정했던 "따뜻하고 사적인(웜 브라운)"
  톤은 2026-07-31 파스텔로 대체([[../../projects/concepts/decisions/결정_가족아카이브_파스텔전환_20260731]])된
  뒤, 같은 날 분홍/연두/살구/하늘 4개 테마를 전부 선택 가능하게 하고 **기본값은 살구(apricot)**로
  재조정됨([[../../projects/concepts/decisions/결정_가족아카이브_색상테마전환_20260731]]) — "하늘색
  고정"이 아니라 사용자가 Nav의 🎨 버튼으로 언제든 바꿀 수 있는 4색 팔레트 중 하나로 이해할 것.
  차갑고 사무적인 톤은 여전히 금지, 카드·버튼은 큰 라운드(`rounded-xl`/`rounded-full`)로 각짐을
  줄인다. 배경은 상단 75% 테마 색 → 하단 25% 흰색(다크모드는 어두운 배경)으로 이어지는 그라데이션.
- **색상 토큰** (`app/globals.css`의 `@theme`+`:root[data-theme=...]`에 정의됨, `lib/theme.ts`의
  `THEMES` 배열이 canonical 목록):
  | 토큰 | 라이트(테마 무관 공통) | 다크(공통) | 용도 |
  |---|---|---|---|
  | `background`(솔리드 폴백) | `#FFFFFF` | `#12181D` | 그라데이션 종점 |
  | `surface` | `#FFFFFF` | `#1B2226` | 카드/입력창 배경 |
  | `foreground` | `#22262B` | `#E7ECEF` | 본문 텍스트 |
  | `muted` | `#64707A` | `#93A0AA` | 보조 텍스트 |
  | `border` | `#DDE3E7` | `#2B343B` | 테두리 |
  | 삭제(danger) | 기존 `red-600`/`red-400` 유지 | 동일 | 경고 신호 명확성 우선, 톤 전환과 무관하게 유지 |

  `accent`/`bg-gradient-from`은 선택된 테마에 따라 달라짐(라이트/다크 각각 별도 값):
  | 테마 | `accent`(라이트/다크) | `bg-gradient-from`(라이트/다크) |
  |---|---|---|
  | 살구(apricot, 기본값) | `#E8935F` / `#F0A873` | `#FDE1D3` / `#2E2019` |
  | 하늘(sky) | `#3B82F6` / `#5B9BD9` | `#CFEAFB` / `#16222E` |
  | 분홍(pink) | `#EC6FA0` / `#F08FBB` | `#FBD8E8` / `#2E1C26` |
  | 연두(lime) | `#5A9C2F` / `#8FC65A` | `#DFF2C8` / `#1E2A18` |

  디자인 작업 시 특정 테마의 hex를 하드코딩하지 말고 `var(--accent)` 등 CSS 변수/Tailwind
  `bg-accent` 계열 유틸리티를 쓴다 — 그래야 4개 테마 전부에서 자동으로 맞는 색이 적용된다.
- **공통 컴포넌트 클래스** (`app/globals.css`의 `@layer components`에 정의): `.btn-primary`(accent
  배경 버튼), `.btn-outline`(테두리 버튼), `.btn-danger`(빨간 텍스트, 삭제 전용), `.btn-tinted`
  (accent 15% 불투명도 배경, ⋮ 관리 버튼 등에 사용), `.card`(앨범/사진 카드), `.input`(텍스트 입력),
  `.select`(셀렉트, 너비 상한 있음), `.toast-bubble`(말풍선 모양, 팝인 애니메이션 — 특정 요소를
  가리킬 때), `.toast-flat`(화살표 없는 둥근 사각형 — 화면 최하단 고정 등 특정 요소를 안 가리킬 때)
  — 화면마다 매번 긴 유틸리티 클래스를 반복하지 말고 이 클래스들을 우선 사용한다. 버튼류는 전부
  고정 높이(`h-10`)+`whitespace-nowrap`이 적용돼 있어 텍스트 길이가 달라도 크기가 들쭉날쭉해지지
  않는다 — 새로 만드는 버튼도 이 규칙을 따른다. 말풍선/토스트류에 자동 사라짐이 필요하면
  `lib/useAutoFade.ts` 훅(3초 뒤 페이드, 클릭 시 즉시 페이드)을 재사용한다. 새 화면에서 반복이
  생기면 이 목록에 추가하고 이 스킬 문서도 함께 갱신.
- 폰트는 기존 Geist Sans 유지(변경 안 함) — 톤 표현은 색상·라운드·간격으로 충분.
- **사진 확대는 PhotoSwipe 사용**: 별도 `PhotoLightbox.tsx` 컴포넌트는 앨범중심UX재설계 때 제거됨
  — 현재는 `components/AlbumGrid.tsx`가 그리드 렌더링+`PhotoSwipeLightbox` 초기화+롱프레스 다중선택+
  ⋮ 관리 메뉴(이동/삭제)를 한 컴포넌트로 통합한 표준 패턴. 새 화면에서 사진을 확대 가능하게 하려면
  직접 터치 이벤트를 구현하지 말고 이 컴포넌트를 재사용하거나 같은 패턴을 따른다. 라이트박스
  위에 뜨는 상단바/관리메뉴는 앱 테마와 무관하게 항상 밝은 배경 고정(`.pswp .pswp__top-bar`,
  `components/DotsIcon.tsx`의 `DOTS_ICON_HTML`) — 사진 위 오버레이는 테마 일치보다 대비 일관성이
  중요하다는 판단. z-index는 PhotoSwipe 루트(`--pswp-root-z-index: 100000`)보다 반드시 높게
  잡을 것 — 낮으면 사진 레이어에 가려지고 클릭도 씹힌다(실제 겪은 버그).

## 순서
1. **최신 확인** — 작업 시작 전 `projects/concepts/프로젝트_가족아카이브.md`를 다시 읽어 위 "핵심 컨텍스트"가 그 사이 바뀌지 않았는지 확인(project-log로 갱신됐을 수 있음).
2. **구현** — `<family-archive 저장소 로컬 경로>`에서 실제 UI 컴포넌트/스타일/레이아웃 코드를 작성·수정한다. cwd·git 안전수칙은 `.claude/skills/_shared/implementation-conventions.md` 참고.
3. **새 설계 결정 발생 시** — 스타일링 라이브러리 선택처럼 재사용 가치 있는 결정이 나오면 코드부터 짜지 말고 `project-log`로 wiki에 먼저 남긴 뒤 구현하고, 이 스킬의 "핵심 컨텍스트"도 함께 갱신한다.
4. **완료** — `family-archive`는 매 작업 단위 종료 시 사용자에게 커밋·푸시 여부를 확인한다(자동 아님). wiki 쪽 파일을 바꿨다면 규칙 #1에 따라 자동 커밋·푸시.
