# 이력서 디자인·산출 규약

이력서는 HTML로 작성하고 헤드리스 Chrome으로 PDF를 뽑는다.
직전 최신 초안 HTML이 실질 템플릿이므로, 새로 만들지 말고 **복사해서 고친다**.

---

## 1. 파일 위치·이름

```
career/raw/이력서/초안/
├── assets/                                  # 캡처 이미지 등 (상대경로로 참조)
├── 이력서_YYMMDD_<변경요지>_v<n>.html
└── 이력서_YYMMDD_<변경요지>_v<n>.pdf
```

- 날짜는 `date +%y%m%d`로 확인해서 쓴다. 세션 중 마지막으로 본 날짜를 재사용하지 않는다.
- 기존 파일은 수정하지 않는다(raw 불변 원칙). 항상 새 버전 파일을 만든다.

---

## 2. 색·톤

원본 이력서의 정체성은 **보라색 하나만 절제해서 쓰는 미니멀 톤**이다.

| 용도 | 값 |
|---|---|
| 액센트(구분선, 좌측 바) | `#6c5ce7` |
| 파스텔 배경(칩, 태그, 타일) | `#f2f0fb` / 테두리 `#e3ddf7` / 글자 `#4b3fa0` |
| 형광 하이라이트 | `#fdf1a8` |
| 본문 글자 | `#1a1a1a`, 보조 텍스트 `#555`~`#888` |

- 강조하려고 **새로운 계열 색(빨강 등)의 콜아웃 박스를 만들지 않는다.** 기존 보라 좌측 바로 충분하다.
- 반대로 무채색으로 과도하게 되돌리지도 않는다. 다이어그램 안에서 색이 의미를 가질 때
  (배제=파스텔 레드 `#fbeaea`/`#e3a6a6`, 채택=파스텔 그린 `#e8f6ec`/`#8ccb9e`,
  진단=파스텔 옐로 `#fdf1a8`/`#e0c94f`)는 절제된 채색을 쓴다.
- **프로젝트 제목(`.project-title`)은 액센트 계열 글자색(`#4b3fa0`)을 쓴다.** 검정(`#1a1a1a`)으로
  두면 인접 프로젝트 사이 경계가 옅어져 어디까지가 한 프로젝트인지 구분이 안 된다는 지적을 받았다
  (2026-08-09). 새 색을 만들지 않고 기존 팔레트의 `edu-org`/`stack-cat`와 같은 색을 재사용한다.

## 3. 레이아웃

- `@page { size: A4; margin: 11mm 14mm; }`
- 본문 `font-size: 9.4px` 내외, `line-height: 1.38`. 분량이 늘면 폰트가 아니라 문장을 줄인다.
- 폰트: `'Pretendard', 'Apple SD Gothic Neo', '맑은 고딕', 'Malgun Gothic', sans-serif`
- 상단 프로필: 이름 + 연락 수단을 클릭 가능한 `<a>`로. 지역은 넣지 않는다.
  - 이메일 `mailto:`, 전화 `tel:`, 블로그·깃허브는 `https://`
  - PDF에서도 앵커가 살아있으므로 링크는 반드시 `<a href>`로 감싼다
- 프로젝트(`.project`) 사이는 얇은 회색 상단 테두리(`border-top: 1px solid #eae7f7`)로 구분한다
  (첫 프로젝트는 `:first-of-type`으로 제외). 간격만으로는 다음 프로젝트로 넘어간 것이 잘
  안 보인다는 지적을 받아 2026-08-09 추가.

## 4. 다이어그램 규칙

인라인 SVG로 그린다. 과거 반려 사유에서 도출된 규칙이다.

1. **한 다이어그램에 성격이 다른 두 층을 섞지 않는다.**
   "어떤 방법을 골랐나(의사결정)"와 "어떻게 처리되나(실행 흐름)"는 별개 다이어그램으로 나눈다.
   과거 이 둘을 한 그림에 넣었다가 "위아래 박스가 무슨 관계인지 모르겠다"는 반려를 받았다.
   다이어그램 개수가 늘어나는 것은 문제가 아니다. 읽히지 않는 것이 문제다.
2. **의미 없는 화살표를 그리지 않는다.** 화살표는 "무엇이 무엇으로 흐르는가"가 분명할 때만 쓴다.
   불명확하면 화살표를 추가하지 말고 **제거하고 레이아웃 간격·색으로** 관계를 표현한다.
3. 화살표에는 가능하면 **라벨**을 붙인다(무엇이 전달되는지).
4. 끝점이 허공에서 끊기는 선이 없는지 좌표를 확인한다.
5. 박스 안 텍스트는 "이름 + 한 줄 설명" 두 줄까지. 세 줄 이상이면 다이어그램이 아니라 표가 맞다.

## 5. 이미지

- `assets/` 상대경로로 참조. 헤드리스 Chrome이 로컬 파일을 그대로 렌더링한다.
- 외부에 넓게 도는 문서이므로 개인 데이터가 담긴 캡처는 **모자이크 버전**만 쓴다.

---

## 6. PDF 생성

```bash
# Windows (현재 작업 환경)
"/c/Program Files/Google/Chrome/Application/chrome.exe" \
  --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="<절대경로>.pdf" \
  "file://<절대경로>.html"

# macOS
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="<절대경로>.pdf" \
  "file://<절대경로>.html"
```

- 파일명에 한글이 있어도 그대로 동작한다(경로는 따옴표로 감싼다).
- 생성 후 파일 크기가 0이 아닌지, 이미지가 포함됐는지 확인한다.
- 페이지 수가 의도보다 늘었으면 폰트를 줄이기 전에 **문장을 줄인다.**

## 7. 웹 사이트 재배포 (PDF와 항상 같이)

이력서는 PDF와 정적 웹 페이지 **두 가지로 배포**된다. PDF만 갱신하고 사이트를 두면
링크로 이력서를 본 사람이 옛 버전을 읽게 되므로, §6 직후에 반드시 이어서 한다.

- 사이트: <https://seunghyeon-resume.pages.dev>
- 저장소: 웹 이력서 저장소 (로컬 클론 경로는 환경에 따라 다름)
- 배경·설계 근거: 위키 [[career/concepts/이력서_웹배포]]

```bash
cd <seunghyeon-resume 저장소 로컬 경로>
cp "<위키>/career/raw/이력서/초안/이력서_YYMMDD_<요지>_v<n>.html" src/resume.html
cp "<위키>/career/raw/이력서/초안/이력서_YYMMDD_<요지>_v<n>.pdf"  src/resume.pdf
npm run deploy        # build.mjs → wrangler pages deploy
```

주의사항.

1. **이미지가 늘었으면** `src/assets/`에 **ASCII 파일명**으로 넣고 `build.mjs`의 치환 목록에 한 줄 추가한다.
   한글 파일명은 CDN 경로에서 퍼센트 인코딩돼 깨지기 쉬워 빌드 시 ASCII로 바꾼다.
2. **웹폰트를 추가하지 않는다.** 현재 PDF는 Malgun Gothic으로 렌더되므로 Pretendard 등을 로드하면
   사이트와 PDF의 글꼴·줄바꿈이 어긋난다. PDF 쪽 폰트를 바꾸기로 결정한 경우에만 같이 바꾼다.
3. `src/`의 HTML은 위키 초안의 **사본**이다. 원본을 경로로 참조하지 않으므로 복사 단계를 빼먹으면
   사이트만 옛 버전으로 남는다.
4. 배포 후 `curl -sSI https://seunghyeon-resume.pages.dev/`로 200을 확인하고, 저장소에
   `git add -A && git commit && git push`까지 한다(위키와 별개 저장소이므로 커밋도 따로).
