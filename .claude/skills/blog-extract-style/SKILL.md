# blog-extract-style

사용자의 글 샘플을 분석해 문체 프로필을 추출하고 저장한다.
여러 번 실행할수록 프로필이 정교해진다.

> **스킬 한계**: 이 프로필은 LLM 기반 분석이므로 샘플이 짧거나 장르가 혼재할 경우 정확도가 낮을 수 있다.

---

## 언제
- 트리거: "문체 학습시켜줘", "스타일 프로필 갱신해줘", "이 글로 문체 추가 학습해줘".

---

## 실행 흐름

### 1. 샘플 수집

사용자가 글 샘플을 함께 제공하지 않았다면 요청한다.

> "분석할 글 샘플을 붙여넣어 주세요. 블로그 글처럼 **같은 장르**의 글일수록 정확합니다.
> 장르가 다른 글(블로그 + 메모 혼합 등)을 함께 제공하면 문체가 평균화되어 개인 특성이 희석될 수 있습니다.
>
> 권장: 총 누적 2,000자 이상 / 충분: 5,000자 이상"

샘플이 단 1개이더라도 분석을 진행한다. 단, 샘플이 300자 미만이면 다음을 안내한다.

> "샘플이 짧아 일부 항목은 추정이 포함될 수 있습니다. 샘플이 많아질수록 프로파일이 정확해집니다."

새 샘플은 (아직 raw로 편입되지 않았다면) `blog/raw/`에도 원문 그대로 저장해 원재료로 남긴다 — raw 편입은 이 스킬이 아니라 `wiki-ingest` 패턴을 따른다(WebFetch로 AI 가공된 텍스트를 쓰지 않는다는 원칙은 `blog/index.md` 참고).

**샘플 자격 (반드시 확인)**: `blog-writer`가 초안을 쓴 글은 사용자가 일부를 고쳤더라도 **학습 샘플로 쓰지 않고 raw에도 넣지 않는다**. AI가 쓴 문장을 프로필로 학습해 다시 그 문체로 쓰는 순환이 생기면 문체가 원본에서 멀어져도 감지할 수 없기 때문이다. 사용자가 이런 글을 샘플로 제시하면 진행하기 전에 "이 글은 AI 초안이 섞여 있는데 학습에 써도 괜찮은지" 확인한다. 사용자가 **처음부터 직접 쓴 글**만 기본 자격이 있다(기준 근거: `blog/index.md`의 raw 편입 기준).

### 2. 기존 프로필 확인

`blog/concepts/스타일_프로필.md`가 존재하면 반드시 먼저 읽는다.

- **존재하는 경우**: 기존 내용을 유지하되 아래 충돌 처리 기준에 따라 보완/수정한다.
- **존재하지 않는 경우**: 새로 작성한다(frontmatter는 `type: concept`, `domain: blog`, `sources:`에 사용된 raw 링크 포함).

**누적 실행 시 충돌 처리 기준**

| 상황 | 처리 방식 |
|---|---|
| 2개 이상 샘플에서 일관되게 관찰된 특성 | 확정 기록 |
| 샘플 1개에서만 관찰된 특성 | `경향 있음(n=1)` 으로 표기 |
| 샘플 간 충돌 (예: 1차-해요체, 2차-합니다체) | `(샘플별 상이: 샘플1-해요체, 샘플2-합니다체)` 로 병기 |

---

### 3. 스타일 분석

아래 6개 영역을 분석한다.

**분석 원칙**
- 각 항목은 샘플에서 **직접 관찰된 근거**만 기록한다. 추측이나 일반론은 쓰지 않는다.
- 관찰되지 않은 항목은 `(샘플 부족으로 미확인)`으로 표기한다.
- **각 항목마다 샘플에서 직접 발췌한 예시 표현을 1~2개 반드시 포함한다.**
- 샘플 1개에서만 관찰된 특성은 `경향 있음(n=1)`으로 표기한다.
- 샘플이 1개일 때 D·E 영역의 패턴/경향 항목은 `(샘플 1개, 경향 판단 불가)`로 표기한다.

#### A. 어투 / 격식 수준
- 문체: 합니다체 / 해요체 / 해체 / 혼용 여부
- 독자 호칭 방식: "여러분", "독자", 호칭 없음 등
- 자기 지칭 방식: "나는" / "저는" / 주어 생략
- 전반적 격식 수준: 격식체 / 구어체 / 혼용

#### B. 문장 단위 패턴
- 문장 길이 경향, 종결 어미 형태 선호, 문장 끝 뉘앙스
- 줄임표(`...`)·괄호·대시(`-`)·em-dash(`—`) 사용 여부와 빈도 — 실제 사용 예 발췌
- 느낌표/이모지 사용 여부, 의문문(자문자답) 사용 경향

#### C. 어휘 선택 패턴
- 한자어 사용 밀도, 한/영 혼용 방식, 반복적으로 나타나는 특징적 표현·어휘
- 기술 용어 처리 방식

#### D. 구조 / 포맷 패턴
- 소제목 스타일(명사형/질문형/구어체형), 대시-부제 병기 여부
- 리스트 vs 산문 선호도, 코드 블록 전후 설명 방식
- 단락 길이 및 구조(전형적 문장 수 범위, 단독 1문장 단락 등장 여부)

#### E. 내러티브 패턴
- 글 시작 방식(문제 제기/배경 설명/결론 먼저/경험담)
- 글 마무리 방식(요약/소감/열린 결말/다음 예고)
- 자주 사용하는 전환 표현, 비유/예시 사용 방식

#### F. 감정 / 태도 표현 패턴
- 어려움·실패를 표현하는 방식, 발견·이해 순간을 표현하는 방식
- 유머·자조·감탄 표현 사용 여부, 의견/입장을 드러내는 강도

---

### 4. 프로필 저장

분석 결과를 `blog/concepts/스타일_프로필.md`에 저장한다. frontmatter는 다음을 따른다.

```yaml
---
type: concept
domain: blog
tags: [blog, 문체, 스타일프로필]
updated: YYYY-MM-DD
sources:
  - "[[raw/새로_추가된_샘플_파일명]]"
  - (기존 sources 유지 + 신규 추가)
status: 진행중
---
```

본문 형식은 기존 `blog/concepts/스타일_프로필.md`의 A~F 영역 + 대표 표현 모음 구조를 그대로 따른다.

---

### 5. 완료 안내

저장 후 다음을 사용자에게 출력한다.
- 프로필이 저장된 경로
- 이번 샘플에서 가장 뚜렷하게 관찰된 특징 2~3가지 요약
- 현재 누적 샘플 수와 총 분량
- 샘플이 1~2개이거나 총 분량이 2,000자 미만인 경우: "샘플을 추가할수록 프로필이 정교해집니다. blog-extract-style을 다시 실행해 샘플을 추가할 수 있습니다."
