# 입력 출처

피드백에 필요한 입력은 **현재 날짜**와 **대상 태스크**다. 날짜는 반드시 `date +%Y-%m-%d`로
확인한다. 기억이나 대화 맥락에서 추정하지 않는다.

## 멘토링 노션 "액션 아이템" DB

태스크 출처다. 수집은 `scripts/notion_tasks.py`가 맡는다.

```
python scripts/notion_tasks.py              # 기본 필터
python scripts/notion_tasks.py --all-open   # 예정 포함, 마감 없는 것도
```

**기본 필터는 상태가 `진행 중` 또는 `완료 대기`이면서 마감일이 오늘 이전인 태스크**다(사용자 확정).

마감일이 없는 태스크는 기한 대조가 불가능하므로 빠진다. 다만 여기에 **매일 하는 상시 과제**가
섞여 있다는 점은 알아야 한다 — 예컨대 문제 풀이는 매일의 과제라 일부러 마감을 두지 않았다.
수행 여부는 이 DB에 없으므로 이 입력만으로는 판정할 수 없고, 판정하려면 다른 입력이 필요하다.

스킬 안에서 매번 API를 호출하지 않는다. "기한이 며칠 지났다"는 계산에 판단이 개입할 여지가
없으므로 결정적인 코드가 맡는 편이 빠르고 실패 지점이 적다.

### 속성

| 속성 | 타입 | 값 |
|---|---|---|
| 할 일 | title | |
| 상태 | select | 예정 / 진행 중 / 완료 대기 / 완료 / 보류 |
| 마감일 | date | 비어 있는 태스크가 꽤 있다 |
| 유형 | select | 블로그, 오픈소스, 사이드 프로젝트, 이력서/포폴, 면접 준비, 서비스, 브랜딩, 기타 |
| D-Day | formula | |
| 주간 일지 · 상위/하위 항목 · 상위/하위 작업 | relation | 현재 읽지 않는다 |

### 반드시 알고 있어야 할 두 가지

**`완료 대기`는 미착수가 아니다.** 본인은 작업을 끝냈고 **멘토 확인만 남은 상태**다. 이걸 미착수로
읽으면 진단이 정반대가 된다(2026-08-19 실제로 그렇게 틀렸다).

멘토는 **매일** 확인한다. 코멘트를 달아 1~2일 안에 대부분 완료로 넘어가지만, 피드백이 붙거나 추가
과제가 생기면 며칠 머물기도 한다. **며칠째 완료 대기인 것을 문제로 삼지 않는다**(2026-08-20 확정).
그래서 수집 스크립트는 완료 대기에 지연일을 매기지 않는다.

**목표는 대부분 본인이 아니라 멘토가 정한다.** 따라서 이 태스크들에는 외부 의존성이 걸려 있다.
"스스로 정한 목표라 무게가 가볍다"는 식으로 읽으면 안 된다(같은 날 이 오독도 있었다).

## 자격증명

`.secrets/notion.json`의 `mentoring` 절에 있다. 이 DB는 **사용자 본인 워크스페이스가 아니라 멘토
워크스페이스**에 있어, 위키의 기본 토큰(`api_token`)으로는 접근되지 않는다. 노션 내부 통합은
만들어진 워크스페이스 안에서만 동작하기 때문이며, 멘토가 발급해 전달한 별도 토큰을 쓴다.

## 자동 실행

현재는 수동 실행이다. 자동화(`/loop`, `schedule`)는 피드백 품질을 조정한 뒤에 붙인다.
붙일 때 유의할 점 하나 — 자동 실행이면 아무도 보지 않는 세션에서 돌 수 있다. 그때는 저장된
파일이 결과물의 전부이므로, 저장 서식이 그 자체로 읽히도록 유지해야 한다.
