# project-kickoff

새 사이드 프로젝트를 정보수집·논의를 통해 MVP 요구사항 페이지로 만든다(특수 ingest). 실제 개발은 별도 저장소에서 진행하고, 이 위키에는 설계·요구사항·의사결정만 남긴다.

## 언제
- 트리거: "<프로젝트> 시작할래", "새 프로젝트 아이디어 있어", "MVP 정의하자", "이 프로젝트 설계하고 싶어".
- 이미 `projects/concepts/프로젝트_<이름>.md`가 존재하면 이 스킬이 아니라 `project-log`를 쓴다.

## 순서
1. **범위 확인** — 프로젝트명, 한 줄 목적, 왜 지금 하는가. 모호하면 AskUserQuestion.
2. **정보수집·논의** — 아래 항목을 대화로 채운다. 한 번에 몰아 묻지 말고 답변에 따라 후속 질문으로 좁혀간다.
   - 문제 정의: 지금 무엇이 불편한가 / 왜 필요한가
   - 타겟 사용자와 범위(사용자가 명시한 대상 이상으로 임의 확장하지 않는다)
   - 핵심 기능 후보와 우선순위 — MVP에 포함 vs 이번엔 제외를 명시적으로 가른다
   - 제약사항(기술 스택 선호, 시간, 운영 주체, 데이터 소스 등)
   - 성공 기준: 무엇이 되면 "MVP로 충분하다"고 볼 것인가
3. **페이지 생성** — `projects/concepts/프로젝트_<이름>.md` 신설. frontmatter는 `type: concept`, `domain: projects`, `status: 진행중`, `sources:`(대화 자체가 출처이므로 비워두거나 관련 raw가 있으면 링크). 본문 구조:
   개요/목적 → 타겟 사용자 → MVP 요구사항(포함/제외 표 또는 목록) → 제약사항 → 성공 기준 → 설계 로그(초기엔 "아직 없음") → 관련 페이지.
4. **링크** — 고아 페이지 방지를 위해 `projects/index.md`의 프로젝트 표에 이 페이지로 나가는 행 추가.
5. **인덱스/로그** — `projects/index.md` 갱신, 루트 `log.md`에 `## [YYYY-MM-DD] ingest | 프로젝트 시작: 제목` append.
6. **완료** — 규칙 #1에 따라 커밋 & 푸시.
